Configurar Supabase Realtime

Qué hay que configurar en Supabase para que una app reciba en vivo los cambios de una tabla, sin refrescar la página.

En todo el documento, reemplazá <nombre-de-tabla> por el nombre real de tu tabla (por ejemplo, Productos).

1Habilitar la tabla en la publicación de Realtime

Realtime solo envía cambios de las tablas que están en la publicación supabase_realtime. Viene apagado para todas las tablas.

Desde el panel

  1. Ir a Database → Publications.
  2. En la fila supabase_realtime, hacer clic en el contador de tablas (o en Edit).
  3. Activar el interruptor de la tabla <nombre-de-tabla>.

También se puede activar desde Table Editor → <nombre-de-tabla>, con el botón Realtime off/on de la barra superior.

Desde el SQL Editor

alter publication supabase_realtime add table public."<nombre-de-tabla>";

Verificar

select schemaname, tablename
from pg_publication_tables
where pubname = 'supabase_realtime';

Tiene que aparecer una fila con public | <nombre-de-tabla>.

Ojo con las mayúsculas: si el nombre de la tabla tiene mayúsculas (por ejemplo, Productos), en SQL hay que escribirlo entre comillas dobles ("Productos"). En el código, table: '<nombre-de-tabla>' tiene que coincidir exactamente con el nombre en la base.

2Políticas de lectura (RLS)

Realtime respeta Row Level Security. Si RLS está activo y no hay una policy de SELECT para el rol del usuario, la suscripción se conecta pero nunca llegan eventos. El select('*') inicial también devuelve una lista vacía.

Desde el panel

  1. Ir a Authentication → Policies (o Table Editor → <nombre-de-tabla> → RLS policies).
  2. Si la tabla dice RLS disabled, hacer clic en Enable RLS.
  3. Create policy, elegir la operación SELECT, el rol authenticated y la expresión USING igual a true.
  4. Repetir para INSERT (con WITH CHECK igual a true) para poder insertar filas desde la app.

Desde el SQL Editor

-- Activar RLS en la tabla
alter table public."<nombre-de-tabla>" enable row level security;

-- Leer: cualquier usuario logueado
create policy "Usuarios logueados pueden leer"
on public."<nombre-de-tabla>"
for select
to authenticated
using (true);

-- Insertar: cualquier usuario logueado
create policy "Usuarios logueados pueden insertar"
on public."<nombre-de-tabla>"
for insert
to authenticated
with check (true);
Estas policies usan el rol authenticated, pensado para apps con login: hay que haber iniciado sesión para ver los cambios. Para que también funcione sin login, reemplazá to authenticated por to anon, authenticated.

Verificar

select policyname, cmd, roles
from pg_policies
where tablename = '<nombre-de-tabla>';

3Ajustes de Realtime del proyecto

En Project Settings → Realtime revisá que Allow public access esté activado. Un canal creado con supabase.channel('nombre-del-canal'), sin private: true, es público. Si el proyecto solo acepta canales privados, la suscripción falla con CHANNEL_ERROR.

4Opcional: datos completos en UPDATE y DELETE

Por defecto, en los eventos UPDATE y DELETE, payload.old solo trae la clave primaria. Si tu app vuelve a consultar la tabla entera ante cada cambio, no lo necesitás. Si más adelante querés usar payload.old completo:

alter table public."<nombre-de-tabla>" replica identity full;

5Probarlo

  1. Correr la app con ng serve (e iniciar sesión, si las policies usan authenticated).
  2. Abrir la pantalla que muestra la tabla en dos pestañas o en dos navegadores.
  3. Insertar una fila en una pestaña: tiene que aparecer en la otra al instante.
  4. También podés insertar una fila desde el Table Editor de Supabase y verla aparecer en la app.

6Si no funciona

SíntomaCausa probable
La lista inicial carga, pero los cambios no lleganLa tabla no está en la publicación supabase_realtime (paso 1).
La lista sale vacía y tampoco llegan cambiosRLS activo sin policy de SELECT para tu rol, o no iniciaste sesión (paso 2).
Estado CHANNEL_ERROR al suscribirseAcceso público a Realtime deshabilitado (paso 3) o URL/key incorrectas en environment.ts.
Error al insertar una filaFalta la policy de INSERT (paso 2).
Error relation "..." does not existEl nombre tiene mayúsculas y faltan las comillas dobles en el SQL.

✓Checklist

  • <nombre-de-tabla> agregada a supabase_realtime
  • RLS activo con policy de SELECT para authenticated (y anon si hace falta)
  • Policy de INSERT para poder agregar desde la app
  • Allow public access activado en los ajustes de Realtime
  • Probado con dos pestañas abiertas
